# FlowSpace ชุดเคสการทดสอบระบบคานบัน (Test Cases)

> **คำประกาศความถูกต้อง**: เอกสารนี้อ้างอิงฟังก์ชันการทำงานจริงจากโค้ดเบส `FlowSpace` บนกิ่ง `main` (Commit: `f0737a0`) เป็นหลัก โดยมีเอกสารคู่มือเป็นข้อมูลประกอบ รายละเอียดเชิงโค้ด (`ไฟล์:บรรทัด` และเอนด์พอยต์ API) ถูกรวบรวมไว้ในภาคผนวกท้ายเอกสาร ส่วนเนื้อหาหลักใช้ภาษาทางธุรกิจและตรงตามมาตรฐานการทดสอบที่สามารถนำไปปฏิบัติได้จริง

## ส่วนนำทาง (คู่มือแนวทางการทดสอบ)

### 1. บทบาทและหน้าที่ในระบบ
FlowSpace คือแพลตฟอร์มบอร์ดคานบันสำหรับการทำงานร่วมกันในทีมแบบ Real-time ประกอบด้วยการแบ่งแยกสิทธิ์ตามบทบาทอย่างเข้มงวด

| บทบาท | หน้าที่และความรับผิดชอบทางธุรกิจ |
|---|---|
| **Project Owner (เจ้าของโปรเจกต์)** | สร้างและลบโปรเจกต์, รีเซ็ตรหัสเชิญ, แต่งตั้งและถอดยศสมาชิก, มีอำนาจตัดสินใจสูงสุดในบอร์ด |
| **Admin Member (ผู้ดูแลโปรเจกต์)** | มีสิทธิ์ `MANAGE_PROJECT` สามารถจัดการคอลัมน์, ปรับยศสมาชิกทั่วไป และเตะสมาชิกที่ไม่ใช่ Owner ออกได้ |
| **Editor Member (ผู้ปฏิบัติงาน)** | มีสิทธิ์ `CREATE_TASK` สามารถสร้าง แก้ไข ลากย้าย และจัดการการ์ดงานของตนเองและทีมได้ |
| **QA Member (ผู้ตรวจสอบคุณภาพ)** | มีสิทธิ์ `CREATE_TASK` + `DELETE_TASK` สามารถสร้าง ตรวจสอบ และลบการ์ดงานที่ไม่ถูกต้องทิ้งได้ |
| **Viewer (ผู้สังเกตการณ์)** | มีสิทธิ์ดูข้อมูลในบอร์ดเท่านั้น ไม่สามารถแก้ไข เคลื่อนย้าย หรือลบข้อมูลใดๆ ได้ |

### 3. คำศัพท์สำคัญ
* **รหัสเชิญ (Invite Code)**: รหัส 6 ตัวอักษร (ตัวพิมพ์ใหญ่และตัวเลข เช่น `A9X3F1`) สำหรับให้สมาชิกใหม่เข้าร่วมโปรเจกต์ได้ทันที
* **คอลัมน์ (Column)**: กลุ่มสถานะงานบนบอร์ด (ค่าเริ่มต้น: To Do, Doing, Done)
* **การ์ดงาน (Task Card)**: เอนทิตีที่เก็บชื่องาน รายละเอียด ลำดับความสำคัญ ผู้รับผิดชอบ กำหนดส่ง และรายการงานย่อย
* **Optimistic UI**: การตอบสนองบนหน้าจอทันที 0 วินาทีเมื่อลากหรือกด จากนั้นบันทึกลงเซิร์ฟเวอร์ในเบื้องหลัง

### 4. สัญลักษณ์และแท็ก
* `[P0]`: เคสสำคัญระดับ Smoke Test ที่ระบบต้องผ่าน (มีแท็ก `(SMOKE-n)`)
* `[P1]`: ฟังก์ชันการทำงานหลักและกรณีผิดพลาดสำคัญ
* `[P2]`: กรณีทดสอบขอบเขตและเงื่อนไขย่อย
* `[ความปลอดภัย]`: ตรวจสอบการป้องกัน IDOR, การรั่วไหลของข้อมูล และการเจาะสิทธิ์
* `[ความเสถียร]`: ตรวจสอบการกู้คืนเครือข่าย, Retry Mechanism และ Rate Limit

## 1. การยืนยันตัวตนและการควบคุมอัตราการเรียก (Auth & Rate Limit)

> สิ่งที่ต้องทำก่อน: เปิดเบราว์เซอร์ไปยัง `http://localhost:3000`

### 1.1 โฟลว์การสมัครสมาชิกและการยืนยันอีเมล
- **TC-01-01 การสมัครสมาชิกใหม่และการป้องกัน Deadlock Re-entry** [P0] (SMOKE-1)
  - ขั้นตอน: 1. เข้าไปที่ `/register` 2. กรอกชื่อผู้ใช้ `Tester1`, อีเมล `newuser@flowspace.test`, รหัสผ่าน `Pass1234!` 3. กดปุ่ม «สร้างบัญชี»
  - ผลลัพธ์ที่คาดหวัง: หน้าจอแจ้งเตือนสำเร็จ แสดงการรอเปิดใช้งาน และระบบสร้างโทเค็นยืนยันตัวตนอายุ 15 นาที; หากใช้อีเมลเดิมที่ยังไม่ได้ยืนยันมาสมัครซ้ำ ระบบจะอัปเดตข้อมูลและออกลิงก์ใหม่ให้โดยไม่เกิดข้อผิดพลาดล็อกซ้ำซ้อน

- **TC-01-02 ลิงก์ยืนยันตัวตนอายุ 15 นาทีและการขอส่งใหม่ใน 1 คลิก** [P1] [ความเสถียร]
  - เงื่อนไขเริ่มต้น: มีลิงก์ยืนยันตัวตนที่หมดอายุแล้ว
  - ขั้นตอน: 1. นำลิงก์ที่หมดอายุไปเปิดในช่อง Address Bar แล้วกด Enter
  - ผลลัพธ์ที่คาดหวัง: หน้าเว็บจะเปลี่ยนเส้นทางไปยังหน้าแจ้งเตือนว่า «ลิงก์หมดอายุแล้ว» โดยมีอีเมลเดิมกรอกไว้ให้พร้อมปุ่ม «ส่งอีเมลยืนยันใหม่อีกครั้ง» ในคลิกเดียว

- **TC-01-03 การสกัดกั้นบัญชีที่ยังไม่ยืนยันอีเมล** [P1] [ความปลอดภัย]
  - เงื่อนไขเริ่มต้น: บัญชี `unverified@flowspace.test` ยังไม่ได้กดยืนยันอีเมล
  - ขั้นตอน: 1. เข้าไปที่ `/login` 2. กรอกอีเมลและรหัสผ่านที่ถูกต้อง 3. กด «เข้าสู่ระบบ»
  - ผลลัพธ์ที่คาดหวัง: การเข้าสู่ระบบถูกปฏิเสธ (403 Forbidden) พร้อมข้อความ «กรุณายืนยันอีเมลของคุณก่อน» และมีปุ่มขอส่งอีเมลใหม่ปรากฏขึ้นใต้ฟอร์ม

### 1.2 การเข้าสู่ระบบและการป้องกัน Brute Force
- **TC-01-04 การเข้าสู่ระบบด้วยข้อมูลที่ถูกต้องและการสร้าง HttpOnly Cookie** [P0] (SMOKE-2)
  - ขั้นตอน: 1. เข้าไปที่ `/login` 2. กรอก `owner@flowspace.test` และ `Pass1234!` 3. กด «เข้าสู่ระบบ»
  - ผลลัพธ์ที่คาดหวัง: แสดงข้อความสำเร็จ และเปลี่ยนหน้าไปยัง `/dashboard` ภายใน 1 วินาที พร้อมได้รับ HttpOnly Cookie ชื่อ `auth_token` ในเบราว์เซอร์

- **TC-01-05 การจำกัดอัตราการเรียกของ API ยืนยันตัวตน (Rate Limit 20 rpm)** [P1] [ความปลอดภัย]
  - ขั้นตอน: 1. ยิงรีเควสต์ล็อกอินผิดพลาดติดต่อกัน 21 ครั้งภายในเวลา 60 วินาที
  - ผลลัพธ์ที่คาดหวัง: 20 ครั้งแรกระบบแจ้งรหัสผ่านไม่ถูกต้อง พอถึงครั้งที่ 21 ระบบจะสกัดทันทีด้วย HTTP 429 Too Many Requests พร้อมบอกเวลาที่ต้องรอ

## 2. การจัดการพื้นที่ทำงานและโปรเจกต์ (Projects & Workspaces)

> สิ่งที่ต้องทำก่อน: เข้าสู่ระบบในฐานะ `owner@flowspace.test` และเปิดหน้า `/dashboard`

### 2.1 การสร้างและดูข้อมูลโปรเจกต์
- **TC-02-01 การสร้างโปรเจกต์ใหม่พร้อมสร้างคอลัมน์เริ่มต้น** [P0] (SMOKE-3)
  - ขั้นตอน: 1. กดปุ่ม «➕ สร้างโปรเจกต์» 2. ตั้งชื่อโปรเจกต์และคำอธิบาย 3. กดยืนยัน
  - ผลลัพธ์ที่คาดหวัง: โปรเจกต์ถูกสร้างและปรากฏบนหน้า Dashboard เมื่อคลิกเข้าไปจะมี 3 คอลัมน์เริ่มต้นทันที (To Do, Doing, Done) และได้รับรหัสเชิญ 6 หลัก

- **TC-02-02 การป้องกันการเข้าถึงข้อมูลข้ามโปรเจกต์ (IDOR Prevention)** [P0] [ความปลอดภัย]
  - เงื่อนไขเริ่มต้น: มีโปรเจกต์ของ User A (ID: 101) และของ User B (ID: 102)
  - ขั้นตอน: 1. ล็อกอินด้วยบัญชี User B 2. พยายามเรียกดูหรือแก้ไขโปรเจกต์ ID: 101
  - ผลลัพธ์ที่คาดหวัง: เซิร์ฟเวอร์ตรวจสอบ Session และปฏิเสธด้วย 403 Forbidden ไม่สามารถมองเห็นหรือแก้ไขข้อมูลของ User A ได้

### 2.2 การเชิญเข้าร่วมโปรเจกต์และการออกจากโปรเจกต์
- **TC-02-03 การเข้าร่วมโปรเจกต์ด้วยรหัสเชิญ 6 หลัก** [P1]
  - เงื่อนไขเริ่มต้น: มีรหัสเชิญที่ถูกต้อง เช่น `A9X3F1`
  - ขั้นตอน: 1. ล็อกอินในฐานะสมาชิกใหม่แล้วกด «🔑 กรอกรหัสเชิญ» บน Dashboard 2. ใส่รหัส `A9X3F1` และกดยืนยัน
  - ผลลัพธ์ที่คาดหวัง: แสดงข้อความเข้าร่วมสำเร็จ โปรเจกต์ใหม่จะปรากฏบนบอร์ดทันทีพร้อมสิทธิ์การทำงานร่วมกัน

- **TC-02-04 การปิดรับสมาชิกและการยกเลิกรหัสเชิญ** [P1]
  - ขั้นตอน: 1. เจ้าของโปรเจกต์กดปุ่ม «🔒 ปิดการเชิญ» 2. สมาชิกภายนอกพยายามใช้รหัสเดิมเข้าร่วม
  - ผลลัพธ์ที่คาดหวัง: สมาชิกภายนอกถูกสกัดกั้น ระบบแจ้งว่า «โปรเจกต์นี้ปิดรับสมาชิกผ่านรหัสเชิญแล้ว» ไม่เกิดข้อผิดพลาดของระบบ

- **TC-02-05 การออกจากโปรเจกต์และการปลดภาระงานอัตโนมัติ** [P1] [ความเสถียร]
  - เงื่อนไขเริ่มต้น: สมาชิกมีการ์ดงานที่มอบหมายให้ตนเองอยู่ 2 ใบ
  - ขั้นตอน: 1. สมาชิกกดเลือก «ออกจากโปรเจกต์» และยืนยัน
  - ผลลัพธ์ที่คาดหวัง: สมาชิกถูกนำออกจากโปรเจกต์ โปรเจกต์หายไปจากหน้า Dashboard และการ์ดงาน 2 ใบเดิมจะถูกเปลี่ยนผู้รับผิดชอบเป็น «ยังไม่มอบหมาย» โดยที่การ์ดยังคงอยู่ที่เดิม (ไม่กลายเป็นงานผี)

## 3. การจัดการคอลัมน์คานบัน (Kanban Columns)

> สิ่งที่ต้องทำก่อน: เปิดหน้าบอร์ดคานบัน `http://localhost:3000/project/1`

  - ผลลัพธ์ที่คาดหวัง: คอลัมน์ใหม่ปรากฏขึ้นทันที และเมื่อเปลี่ยนชื่อ ข้อความจะอัปเดตแบบเรียลไทม์ รีเฟรชหน้าแล้วตำแหน่งและชื่อยังคงเดิม

- **TC-03-02 การป้องกันคอลัมน์เป็นศูนย์ (Zero-Column Guard)** [P1] [ความปลอดภัย]
  - เงื่อนไขเริ่มต้น: บอร์ดเหลือคอลัมน์สุดท้ายเพียง 1 คอลัมน์

  - ผลลัพธ์ที่คาดหวัง: ปุ่มลบจะถูกปิดการใช้งาน (Disabled) และหากยิง API โดยตรงจะได้รับ 400 Bad Request ระบุว่า «ต้องมีคอลัมน์เหลืออยู่อย่างน้อย 1 คอลัมน์»

- **TC-03-03 การสกัดกั้นการลบคอลัมน์ที่ยังมีการ์ดงานค้างอยู่** [P1] [ความเสถียร]

  - ขั้นตอน: 1. กดปุ่มลบคอลัมน์ «Doing»
  - ผลลัพธ์ที่คาดหวัง: ระบบแจ้งเตือนว่า «ยังมีงานค้างอยู่ในคอลัมน์นี้ กรุณาย้ายงานออกก่อน» และไม่อนุญาตให้ลบ

## 4. วงจรชีวิตของการ์ดงาน (Tasks & Subtasks)

> สิ่งที่ต้องทำก่อน: เข้าสู่ระบบด้วยสมาชิกที่มีสิทธิ์ `CREATE_TASK`

### 4.1 การสร้างและการย้ายการ์ด
- **TC-04-01 การสร้างการ์ดงานและการตรวจสอบฟิลด์บังคับ** [P0] (SMOKE-4)
  - ขั้นตอน: 1. กด «+ เพิ่มงาน» ในคอลัมน์ To Do 2. ใส่หัวข้อ «พัฒนาระบบชำระเงิน» 3. เลือกลำดับความสำคัญ HIGH 4. มอบหมายผู้รับผิดชอบและบันทึก
  - ผลลัพธ์ที่คาดหวัง: การ์ดงานปรากฏขึ้นทันทีพร้อมป้าย HIGH สีส้มและรูปโปรไฟล์ผู้รับผิดชอบ; หากไม่ใส่หัวข้องาน ระบบจะแจ้งเตือนและไม่อนุญาตให้บันทึก

- **TC-04-02 การลากย้ายการ์ดข้ามคอลัมน์ (Optimistic UI)** [P0] (SMOKE-5)
  - ขั้นตอน: 1. ใช้เมาส์ลากการ์ดงานจาก To Do 2. วางลงในคอลัมน์ Doing
  - ผลลัพธ์ที่คาดหวัง: การ์ดย้ายไปทันทีใน 0 วินาที และบันทึกประวัติการย้ายใน Activity Log ของการ์ดอย่างถูกต้อง

### 4.2 ฟีเจอร์เสริมของการ์ด (Checklist & Comments)
- **TC-04-03 การอัปเดต Checklist และความคืบหน้าของงานย่อย** [P1]
  - ขั้นตอน: 1. เปิดรายละเอียดการ์ด 2. เพิ่มงานย่อย 2 ข้อ 3. ติ๊กถูก 1 ข้อ
  - ผลลัพธ์ที่คาดหวัง: หลอดความคืบหน้าแสดง 50% และบนหน้าบอร์ดการ์ดแสดงตัวเลข `1/2` อย่างถูกต้อง

- **TC-04-04 การแสดงความคิดเห็นและการบันทึกประวัติกิจกรรม** [P1]
  - ขั้นตอน: 1. พิมพ์ความคิดเห็น «ทดสอบระบบเสร็จแล้ว» แล้วกดส่ง
  - ผลลัพธ์ที่คาดหวัง: ความคิดเห็นปรากฏทันที และในแท็บประวัติกิจกรรม (Activity Log) จะมีบันทึกการแสดงความคิดเห็นเพิ่มขึ้นมา 1 รายการ

- **TC-04-05 การป้องกันสิทธิ์การลบการ์ดงาน** [P1] [ความปลอดภัย]
  - เงื่อนไขเริ่มต้น: ล็อกอินด้วยสมาชิกที่มีเฉพาะ `CREATE_TASK` แต่ไม่มีสิทธิ์ `DELETE_TASK`
  - ขั้นตอน: 1. เปิดรายละเอียดการ์ดงานและตรวจสอบปุ่มลบ
  - ผลลัพธ์ที่คาดหวัง: บนหน้าจอจะไม่มีปุ่มลบแสดงขึ้นมา และหากเรียก API ลบโดยตรงจะถูกสกัดกั้นด้วย 403 Forbidden

## 5. การจัดการบทบาทและสิทธิ์ (Roles & RBAC)

> สิ่งที่ต้องทำก่อน: ล็อกอินด้วย Project Owner เข้าสู่เมนูจัดการสมาชิก

### 5.1 การกำหนดบทบาทและการแต่งตั้งสมาชิก
- **TC-05-01 การสร้างบทบาทกำหนดเอง (Custom Role) และกำหนดสิทธิ์** [P1]
  - ขั้นตอน: 1. สร้างบทบาทใหม่ชื่อ «นักพัฒนา Frontend» 2. ติ๊กเฉพาะสิทธิ์ `CREATE_TASK` 3. มอบหมายบทบาทนี้ให้สมาชิก B
  - ผลลัพธ์ที่คาดหวัง: สร้างบทบาทสำเร็จ สมาชิก B สามารถสร้างและลากย้ายการ์ดได้ แต่ไม่สามารถจัดการคอลัมน์หรือเตะสมาชิกคนอื่นได้

- **TC-05-02 การเตะสมาชิกและการคุ้มครอง Owner** [P1] [ความปลอดภัย]
  - ขั้นตอน: 1. ให้ Admin พยายามเตะ Project Owner 2. ให้ Owner สั่งเตะ Admin
  - ผลลัพธ์ที่คาดหวัง: ฝั่ง Admin จะไม่มีปุ่มเตะ Owner และหากยิง API จะถูกสกัดด้วย 403 Forbidden; ส่วน Owner เตะ Admin ได้สำเร็จและงานของ Admin จะถูกปลดออกอัตโนมัติ

> สิ่งที่ต้องทำก่อน: เปิด 2 หน้าต่างเบราว์เซอร์ ล็อกอินเป็น User A (Owner) และ User B (Member) ในโปรเจกต์เดียวกัน

### 6.1 การซิงค์ผ่าน SSE
- **TC-06-01 การซิงค์การเปลี่ยนแปลงของการ์ดงานข้ามหน้าจอแบบเรียลไทม์** [P0] [ความเสถียร] (SMOKE-6)
  - ขั้นตอน: 1. User A ลากการ์ดจาก To Do ไป Doing ในหน้าต่างที่ 1 2. สังเกตหน้าต่างที่ 2
  - ผลลัพธ์ที่คาดหวัง: หน้าต่างที่ 2 อัปเดตตำแหน่งการ์ดตามโดยอัตโนมัติภายใน 1 วินาที โดยไม่ต้องกด F5 รีเฟรชหน้าจอ

- **TC-06-02 การกู้คืนการเชื่อมต่อเมื่อสลับแท็บกลับมา (Tab Re-activation)** [P1] [ความเสถียร]
  - ขั้นตอน: 1. ย่อหน้าต่างที่ 2 ลง 2. User A เพิ่มการ์ดใหม่ในหน้าต่างที่ 1 3. เปิดหน้าต่างที่ 2 กลับขึ้นมา
  - ผลลัพธ์ที่คาดหวัง: หน้าต่างที่ 2 ตรวจจับการกลับมาทำงาน (`visibilitychange`) และดึงข้อมูลล่าสุดมาแสดงผลได้ทันที
